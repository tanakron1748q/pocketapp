## What to build

ผู้ใช้เพิ่มรายรับหรือรายจ่ายจากมือถือหรือ desktop แล้วเห็นรายการที่จัดเก็บจริง รวมหมวดตั้งต้นแยกตามประเภท

## Acceptance criteria

- [ ] กรอกประเภท จำนวนเงิน หมวด และวันที่ได้ โดยคำอธิบายเป็นทางเลือกและวันที่เริ่มต้นเป็นวันนี้
- [ ] มีหมวดตั้งต้นส่วนตัวแยกรายรับ/รายจ่าย เลือกหมวดผิดประเภทหรือของ User อื่นไม่ได้
- [ ] จำนวนเงินตรงถึงสตางค์ จำนวนไม่ถูกต้องและวันที่อนาคตถูกปฏิเสธทั้งจาก UI และ HTTP; ใช้วันที่ไทย
- [ ] ข้อมูลยังอยู่หลัง reload และเปิดจากอุปกรณ์อื่นของบัญชีเดิม เห็นรายการเรียงลำดับและสถานะไม่มีข้อมูล/กำลังบันทึก/ล้มเหลวที่เข้าใจได้
- [ ] มี browser/HTTP tests ของการเพิ่มรายการ ความเที่ยงตรงของเงิน/วันที่ และการป้องกันอ่านหรือสร้างรายการข้าม User
