# Pocketapp — ขอบเขตผลิตภัณฑ์

## ข้อสรุปที่ผู้ใช้ยืนยันแล้ว

- เว็บแอปรองรับมือถือและ desktop พร้อมระบบยืนยันตัวตน
- ผู้ใช้แต่ละคนมีข้อมูลส่วนตัวแยกกัน รุ่นแรกไม่มีบัญชีร่วมกับครอบครัวหรือผู้อื่น
- บันทึกรายรับและรายจ่ายพร้อมคำอธิบายด้วยตนเอง โดยเน้นกรอกได้เร็ว
- Dashboard ตอบว่าเดือนนี้รับเท่าไร จ่ายเท่าไร เหลือเท่าไร และใช้จ่ายกับอะไร
- เงินเหลือประจำเดือนหมายถึงรายรับลบรายจ่ายสุทธิของเดือนนั้น ไม่ใช่ยอดเงินจริงทั้งหมดในธนาคารหรือกระเป๋าเงิน
- มีหมวดหมู่รายรับและรายจ่าย งบรายเดือนแยกหมวด งบคงเหลือ การเปรียบเทียบกับเดือนก่อน และการค้นหา/กรองรายการย้อนหลัง
- มีรายการโปรดเพื่อช่วยกรอกรายการที่บันทึกบ่อย
- รุ่นแรกใช้งานออนไลน์ ข้อมูลต้องตรงกันระหว่างมือถือและ desktop
- การนำเข้าไฟล์ธนาคาร การอ่านสลิป และการทำงานออฟไลน์อยู่นอกขอบเขตรุ่นแรก
- รุ่นแรกใช้รายการโปรดช่วยกรอกข้อมูล รายการเกิดซ้ำอัตโนมัติเลื่อนไปพิจารณาภายหลัง

## ข้อสรุปรอบที่สอง

- เข้าสู่ระบบด้วย Google อย่างเดียว เปิดให้บุคคลอื่นสมัครได้ และข้อมูลแยกตามผู้ใช้
- ส่วนติดต่อภาษาไทย ใช้เงินบาทสกุลเดียว จำนวนเงินละเอียดถึงสตางค์ วันที่นับตามเวลาไทย
- รายการประกอบด้วยประเภทรายรับ/รายจ่าย จำนวนเงิน หมวดหมู่ และวันที่ โดยคำอธิบายเป็นทางเลือก
- วันที่เริ่มต้นเป็นวันนี้ เลือกย้อนหลังได้ แก้ไขรายการได้ และต้องยืนยันก่อนลบรายการ
- มีหมวดตั้งต้นแยกตามรายรับและรายจ่าย ผู้ใช้เพิ่ม เปลี่ยนชื่อ และเก็บหมวดที่เลิกใช้ได้ โดยรักษารายการเก่าไว้
- งบแยกตามหมวดรายจ่าย ใช้งบเดิมต่อในเดือนถัดไป และปรับเฉพาะเดือนได้ ไม่ทบงบเหลือข้ามเดือน
- Dashboard แสดงงบที่ใช้แล้วและงบคงเหลือ การเกินงบไม่ขัดขวางการบันทึกรายจ่าย
- รายการโปรดเติมรายละเอียดให้ แต่ผู้ใช้ต้องยืนยันบันทึกทุกครั้ง
- รุ่นแรกไม่มีการสร้างรายการเกิดซ้ำอัตโนมัติ
- ส่งออกรายการเป็น CSV ได้
- มีการลบบัญชีพร้อมข้อมูลทั้งหมด ต้องยืนยันซ้ำอย่างชัดเจน และกู้คืนไม่ได้

## ข้อสรุปรอบที่สาม

- การโอนเงินระหว่างบัญชีหรือกระเป๋าของผู้ใช้เองไม่บันทึกเป็นรายรับหรือรายจ่าย
- รุ่นแรกไม่ติดตามยอดแยกตามกระเป๋าหรือธนาคาร
- เงินคืนบันทึกด้วยตนเองโดยอ้างอิงรายจ่ายเดิม รองรับบางส่วนและเต็มจำนวน ไม่เชื่อมต่อธนาคาร
- เงินคืนลดรายจ่ายของหมวดเดิมตามวันที่ได้รับเงินจริง จึงอาจทำให้รายจ่ายสุทธิของหมวดในเดือนที่รับเงินคืนติดลบได้
- บันทึกรายการได้เฉพาะวันนี้หรือย้อนหลัง สำหรับเงินที่รับหรือจ่ายจริงแล้ว ค่าใช้จ่ายที่วางแผนไว้ใช้การตั้งงบ
- Dashboard เริ่มที่เดือนปัจจุบันและเลือกเดือนย้อนหลังได้ แสดงรายรับ รายจ่ายสุทธิ เงินเหลือ กราฟรายจ่ายตามหมวด งบคงเหลือ และรายการล่าสุด
- เดือนปัจจุบันเปรียบเทียบช่วงวันที่เท่ากันกับเดือนก่อน เดือนที่จบแล้วเปรียบเทียบเต็มเดือน โดยแสดงช่วงวันที่กำกับ
- เป้าหมายส่งมอบระยะแรกคือเว็บที่กดทดสอบขั้นตอนใช้งานได้ก่อน การตกแต่ง UI เพิ่มเติมทำภายหลัง
- ใช้บริการฟรีทั้งหมด เริ่มจากใช้เองคนเดียว อาจมีแฟนหรือเพื่อนใช้ในอนาคต ยังไม่เน้นรองรับผู้ใช้จำนวนมาก
- การเปิดให้บุคคลอื่นสมัครตามข้อสรุปรอบสองยังเป็นขอบเขตของระบบจริง แต่ผู้ใช้เริ่มต้นมีเพียงเจ้าของโปรเจกต์

## ข้อสรุปรอบที่สี่ — ระบบจริงครบฟีเจอร์

- รุ่นแรกต้องมีฟีเจอร์ที่ตกลงทั้งหมดและใช้งานจริงได้ รวม Google Login และการจัดเก็บข้อมูลจริง ไม่ใช่ต้นแบบที่ใช้ข้อมูลจำลองหรือปุ่มเข้าสู่ระบบทดลอง
- บัญชี Google แต่ละบัญชีเป็นผู้ใช้แยกกัน รายการ หมวดหมู่ งบ รายการโปรด และเงินคืนเป็นข้อมูลส่วนตัวของผู้ใช้นั้น
- การใช้บัญชี Google เดิมบนมือถือและ desktop ต้องเข้าถึงข้อมูลชุดเดียวกัน การเปลี่ยนไปบัญชี Google อื่นต้องเห็นข้อมูลของบัญชีใหม่เท่านั้น
- ระบบต้องป้องกันการอ่าน แก้ไข ลบ และส่งออกข้อมูลข้ามผู้ใช้ รวมถึงเมื่อเข้าถึงรายการผ่าน URL หรือคำขอโดยตรง
- ยอดคืนสะสมต้องไม่เกินยอดรายจ่ายต้นทาง
- หากมีเงินคืนอ้างอิงอยู่ ต้องแก้ไขหรือลบเงินคืนก่อน จึงจะลบรายจ่ายต้นทางหรือลดยอดรายจ่ายให้ต่ำกว่ายอดคืนสะสมได้
- ส่งออก CSV ตามตัวกรองที่เลือก ประกอบด้วยวันที่ ประเภท หมวด จำนวนเงิน คำอธิบาย และรายการอ้างอิงเงินคืน โดยรวมเฉพาะข้อมูลของผู้ใช้ที่เข้าสู่ระบบ
- ลบบัญชีพร้อมข้อมูลทั้งหมดโดยยืนยันตัวตนซ้ำและพิมพ์ข้อความยืนยัน การลบบัญชีในแอปนี้ไม่ใช่การลบบัญชี Google
- เน้นฟังก์ชันที่กดทดสอบได้ครบก่อน แล้วค่อยปรับรายละเอียด UI ภายหลัง โดยยังต้องใช้งานได้บนมือถือและ desktop

## เกณฑ์ตรวจรับหลัก

- ผู้ใช้สองบัญชี Google เข้าสู่ระบบและบันทึกข้อมูลได้ โดยแต่ละบัญชีเข้าถึงได้เฉพาะข้อมูลของตัวเอง
- บัญชี Google เดิมใช้งานข้ามมือถือและ desktop แล้วเห็นข้อมูลตรงกัน
- เพิ่ม แก้ไข ลบ ค้นหา และกรองรายการได้ วันที่ในอนาคตและจำนวนเงินที่ไม่ถูกต้องถูกปฏิเสธ
- จัดการหมวดหมู่ รายการโปรด และงบรายเดือนได้ตามกติกาข้างต้น
- เงินคืนบางส่วน เต็มจำนวน และข้ามเดือนมีผลต่อรายจ่ายสุทธิและงบในเดือนที่รับเงินคืน โดยไม่เพิ่มยอดรายรับ
- Dashboard ใช้ข้อมูลจริง แสดงช่วงวันที่เปรียบเทียบ และคำนวณรายรับ รายจ่ายสุทธิ เงินเหลือ และงบคงเหลือสอดคล้องกัน
- CSV ตรงกับตัวกรองและไม่รวมข้อมูลของผู้ใช้อื่น
- การลบบัญชีต้องผ่านขั้นตอนยืนยัน และไม่ลบข้อมูลของผู้ใช้อื่น

## ข้อตกลงด้าน frontend

- ผู้ใช้ยืนยันใช้ frontend ตามข้อเสนอจากการวิเคราะห์: Next.js 16 App Router, React, TypeScript, Ant Design, Tailwind CSS สำหรับ layout/responsive, Recharts และ pnpm
- ใช้ AntD Form จัดการฟอร์ม และ Zod ตรวจข้อมูลฝั่ง server ตามข้อเสนอที่ลดส่วนซ้ำ ยังไม่เพิ่ม React Hook Form ในชุดเริ่มต้น
- ใช้ไอคอนชุดหลักเดียว โดยข้อเสนอเริ่มต้นคือ Ant Design Icons
- การเลือก vinext หรือ toolchain สำหรับ deploy เป็นประเด็นของ hosting ที่ยังต้องตัดสินใจแยกจากส่วนหน้าจอ

## ความต้องการฐานข้อมูลล่าสุดและเรื่องที่ยังหารือ

- ผู้ใช้ต้องการ Prisma ORM และระบุฐานข้อมูลว่า “postgrest”; การประเมิน hosting รอบนี้ตีความเบื้องต้นว่าหมายถึง PostgreSQL ซึ่งต่างจาก PostgREST ที่เป็นระบบสร้าง HTTP API บน PostgreSQL
- D1 + Drizzle ในเอกสารวิเคราะห์ก่อนหน้าเป็นข้อเสนอเดิม ไม่ใช่ stack ฐานข้อมูลที่ยืนยันแล้ว
- ยังไม่ยืนยันผู้ให้บริการฐานข้อมูล, hosting และการเลือกไลบรารียืนยันตัวตน
- การออกแบบระบบและการนำขึ้นใช้งานต้องอยู่ภายใต้ข้อจำกัดใช้บริการฟรีทั้งหมดและผู้ใช้กลุ่มเล็ก

สถานะ: ยืนยันขอบเขตฟีเจอร์และแนวทาง frontend แล้ว อยู่ระหว่างหารือฐานข้อมูลและ hosting ยังไม่ได้เริ่มพัฒนา
