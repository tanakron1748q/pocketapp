# จัดการหมวดหมู่ — ticket #5

จาก `/dashboard` กด **จัดการหมวดหมู่** เพื่อเพิ่มหมวดรายรับหรือรายจ่าย เปลี่ยนชื่อ หรือเก็บหมวดที่เลิกใช้ หมวดใหม่เลือกในฟอร์มรายการของประเภทเดียวกันได้ทันที ชื่อยาวได้ 1–100 ตัวอักษรหลังตัดช่องว่างหัวท้าย โดยประเภทของหมวดเปลี่ยนภายหลังไม่ได้

การเปลี่ยนชื่อมีผลต่อชื่อที่แสดงในประวัติด้วย การเก็บหมวดเปลี่ยนเพียงสถานะ `archived` ไม่ลบหมวดหรือรายการ หมวดตั้งต้นที่เปลี่ยนชื่อหรือเก็บแล้วจะไม่ถูกสร้างใหม่/รีเซ็ตเมื่อเปิดแอปอีกครั้ง

ฟอร์มรายการใหม่ไม่แสดงหมวดที่เก็บแล้ว และล้างตัวเลือกหากผู้ใช้เพิ่งเก็บหมวดที่เลือกอยู่ การแก้ไขรายการเก่าสามารถคงหมวดเดิมที่เก็บแล้วได้ แต่เปลี่ยนไปหมวดที่เก็บแล้วหมวดอื่นไม่ได้ จึงยังแก้จำนวนเงิน วันที่ และคำอธิบายในประวัติได้

## Migration

ก่อนใช้งานรัน `pnpm db:migrate` เพื่อใช้ `20261028000300_category_archiving` ซึ่งเพิ่ม `categories.archived BOOLEAN NOT NULL DEFAULT false` ข้อมูลเดิมและความสัมพันธ์กับรายการยังอยู่ทั้งหมด

## HTTP contract

ทุก endpoint ตรวจ session และตอบ `Cache-Control: private, no-store` เจ้าของข้อมูลมาจาก session เท่านั้น ทุก mutation ต้องส่ง JSON และ `Origin` ที่ตรงกับ `BETTER_AUTH_URL`

- `GET /api/categories` ส่ง `{ categories: [{ id, name, type, archived }], today }` รวมหมวดที่เก็บแล้วเพื่อใช้แสดงประวัติและหน้าจัดการ
- `POST /api/categories` รับ `{ name, type: "INCOME" | "EXPENSE" }` สำเร็จตอบ 201 พร้อม `{ category }`
- `PATCH /api/categories/ID` รับ `{ name }` เพื่อเปลี่ยนชื่อ หรือ `{ archived: true }` เพื่อเก็บหมวด สำเร็จตอบ 200 พร้อม `{ category }` การเก็บซ้ำปลอดภัย ไม่มีการลบหมวดหรือเปลี่ยนประเภทผ่าน endpoint นี้
- ฟิลด์เกิน เช่น `userId`, `starterKey`, `type` ในคำขอแก้ไข ถูกปฏิเสธด้วย 422 หมวดของผู้ใช้อื่นและ ID ที่ไม่มีอยู่ตอบ 404 เหมือนกัน
- 401 ไม่มี session, 403 origin ไม่ตรง, 415 ไม่ใช่ JSON, 400 JSON ไม่ถูกต้อง, 422 ข้อมูลไม่ผ่านกติกา, 503 จัดเก็บไม่สำเร็จ

`category` ในผลลัพธ์รายการมี `archived` ด้วย การสร้างรายการและการเปลี่ยนหมวดตรวจเจ้าของ ประเภท และสถานะฝั่ง server ภายใน database transaction โดยล็อกหมวดด้วย `FOR SHARE` จนบันทึกเสร็จ จึงป้องกันการเก็บหมวดแทรกระหว่างตรวจและเขียนข้อมูล หากบันทึกเสร็จก่อนเก็บหมวด รายการนั้นถือเป็นประวัติเดิม หากเก็บสำเร็จก่อน คำขอสร้างรายการจะถูกปฏิเสธ

## Verification

`pnpm test:e2e` ใช้ production server กับ PostgreSQL แยกผ่าน Docker และทดสอบบน desktop/mobile รวม:

- เพิ่มทั้งสองประเภทจากหน้าจอ เลือกใช้ทันที และไม่พบในประเภทที่ผิด
- เปลี่ยนชื่อ เก็บหมวด แล้ว reload ยังเห็นหมวดและจำนวนเงินในประวัติ
- แก้ไขรายการที่คงหมวดเดิมที่เก็บแล้วได้ ไม่อนุญาตสร้างรายการใหม่หรือเปลี่ยนไปหมวดที่เก็บแล้ว
- HTTP ข้ามผู้ใช้ ปลอมเจ้าของ/ประเภท validation และ origin ถูกปฏิเสธ
- อีกอุปกรณ์อ่านข้อมูลตรงกัน และร่างจากอุปกรณ์ที่ยังไม่รู้ว่าเก็บหมวดแล้วถูกปฏิเสธโดย server
- หมวดตั้งต้นไม่ถูกรีเซ็ตหลังเปลี่ยนชื่อ/เก็บ และความล้มเหลว/ยกเลิกไม่ทำให้ร่างหรือประวัติหาย

ชุดทดสอบใช้ session fixtures ของระบบเดิม ไม่ใช้ Google จริง ต้องตรวจบน cloud หลังตั้งค่า OAuth/Neon และใช้ migration นี้ โดยตรวจเพิ่ม/เปลี่ยนชื่อ/เก็บหมวดด้วยบัญชีจริงแล้ว reload อีกอุปกรณ์
