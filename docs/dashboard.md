# ภาพรวมรายเดือน — issue #10

เปิด `/dashboard` หลังเข้าสู่ระบบ ส่วน **ภาพรวมรายเดือน** เริ่มจากเดือนปัจจุบันตาม `Asia/Bangkok` เลือกเดือนย้อนหลังได้ ตัวเลือกเดือนในภาพรวมและงบเชื่อมกัน จึงดูยอดรวม กราฟ งบ และรายการล่าสุดของเดือนเดียวกัน ส่วนรายการทั้งหมดด้านล่างยังใช้เงื่อนไขค้นหา/กรองของตัวเอง

## ยอดและช่วงเวลา

- รายรับประจำเดือน = ผลรวมรายรับที่ลงวันที่ในเดือนที่เลือก
- รายจ่ายสุทธิ = รายจ่ายที่ลงวันที่ในเดือน − เงินคืนที่ได้รับในเดือน
- เงินเหลือประจำเดือน = รายรับ − รายจ่ายสุทธิ

เงินเหลือประจำเดือนเป็นกระแสเงินที่ผู้ใช้บันทึก ไม่ใช่ยอดธนาคาร กระเป๋า หรือทรัพย์สินทั้งหมด UI ระบุคำอธิบายนี้ไว้ใกล้ยอดรวม ค่าติดลบแสดงได้ทั้งรายจ่ายสุทธิและเงินเหลือ

ใช้ business dates ใน PostgreSQL `DATE` ตั้งแต่วันแรกถึงก่อนวันแรกของเดือนถัดไป จึงรวมวันสุดท้ายและปีอธิกสุรทินโดยไม่ขึ้นกับ timezone ของอุปกรณ์ ยอดรวมคำนวณด้วยจำนวนเต็มสตางค์/BigInt และส่งเป็นข้อความบาทสองตำแหน่ง

เงินคืนไม่เพิ่มรายรับและไม่ย้อนลดเดือนต้นทาง แต่ลดหมวดปัจจุบันของรายจ่ายต้นทางในเดือนที่ได้รับจริง การแก้วัน/จำนวนเงิน/หมวด หรือเปลี่ยนชื่อและเก็บหมวด สะท้อนในรายงานเมื่อโหลดใหม่

## กราฟ งบ และรายการล่าสุด

กราฟแท่งแนวนอนมีเส้นศูนย์ ค่าบวกอยู่ขวาและค่าติดลบอยู่ซ้าย ไม่มีการทิ้งเงินคืนหรือตัดค่าติดลบให้เป็นศูนย์ ค่าสำหรับวาดกราฟใช้ตัวเลข ส่วนรายการใต้กราฟแสดงชื่อหมวดเต็มและยอดฐานสิบสองตำแหน่งจาก server ให้ตรวจค่าได้แม้ป้ายในกราฟย่อชื่อ หมวดที่สุทธิเป็นศูนย์ยังแสดงในรายการตัวเลข กราฟมี accessible label อธิบายทิศทางค่า

ส่วนงบใช้เดือนเดียวกับภาพรวม แสดงใช้ไปสุทธิ งบคงเหลือ หรือยอดใช้เกินตาม [กติกางบ](budgets.md) พร้อมแก้ค่าตั้งต้นหรือเฉพาะเดือนได้ การกด **โหลดภาพรวมใหม่** โหลดงบใหม่ด้วย

รายการล่าสุดแสดงรายรับ/รายจ่ายไม่เกิน 5 รายการของเดือนที่เลือก เรียงวันที่ล่าสุด เวลาสร้างล่าสุด และ ID ล่าสุดก่อน ไม่แสดงรายการนอกเดือน ส่วนประวัติเงินคืนยังเปิดจากรายจ่ายต้นทางในรายการทั้งหมด

เดือนว่างแสดงยอด 0.00 ข้อความว่าไม่มีข้อมูลกราฟ และไม่มีรายการล่าสุด สถานะกำลังโหลดและข้อผิดพลาดแยกจากข้อมูลว่าง โหลดล้มเหลวไม่แสดงยอดเดือนก่อนหน้าเป็นยอดของเดือนใหม่ กดลองใหม่ได้

การบันทึก/แก้/ลบรายการหรือเงินคืนผ่านหน้าจอเดียวกันจะโหลดภาพรวมและงบใหม่ โดยยังคงเดือนที่เลือกไว้ การเปลี่ยนเดือนเร็วจะยกเลิกการอ่านเดือนก่อนหน้าเพื่อไม่ให้คำตอบเก่าทับเดือนใหม่

## HTTP และความเป็นส่วนตัว

`GET /api/dashboard?month=YYYY-MM` ถ้าไม่ระบุเดือนใช้เดือนปัจจุบันเวลาไทย รับเฉพาะ `month` ไม่รับ userId หรือ field อื่น ไม่มี session ตอบ 401 เดือนหรือ query ผิดตอบ 400 ระบบล้มเหลวตอบ 503 ทุกคำตอบใช้ `Cache-Control: private, no-store`

ผลสำเร็จมี `month`, `income`, `expense`, `refunded`, `netExpense`, `monthlyNet`, `categories` (ยอดรายจ่าย/เงินคืน/สุทธิแยกหมวด) และ `recentTransactions` ข้อมูลทั้งหมดจำกัดด้วย User จาก session ใช้ Repeatable Read transaction เดียวสำหรับรายรับ ยอดและหมวดรายจ่ายสุทธิ และรายการล่าสุด เพื่อให้เป็น snapshot เดียวกัน

งบอ่านผ่าน `/api/budgets?month=YYYY-MM` ตามเดิม เป็นรายงานส่วนตัวของเดือนเดียวกันและไม่เก็บใน shared cache การสลับบัญชีสร้าง workspace ใหม่ตาม User ID และการออกจากระบบใช้การล้าง session เดิมของแอป ไม่มี migration เพิ่มใน ticket นี้

## การตรวจรับ

`pnpm test:e2e dashboard.spec.ts` ใช้ production server กับ PostgreSQL แยก ทดสอบ desktop/mobile:

- เดือนปัจจุบันเวลาไทย เดือนว่าง และการเลือกเดือนย้อนหลัง รวมวันสิ้นเดือน/กุมภาพันธ์ปีอธิกสุรทิน/ข้ามปี
- รายรับ รายจ่ายสุทธิ และเงินเหลือที่ถูกต้องถึงสตางค์ รวมยอดใหญ่หลายรายการ
- เงินคืนข้ามเดือน การแก้วันรับเงินคืน หมวดเปลี่ยนชื่อ/เก็บแล้ว และงบใช้ไป/เหลือที่สัมพันธ์กัน
- กราฟมีทั้งแท่งซ้ายศูนย์และขวาศูนย์ พร้อมตัวเลขสุทธิจริง รายการล่าสุดจำกัด 5 รายการและไม่ข้ามเดือน
- การอัปเดตหลังเพิ่มรายจ่าย retry เมื่อโหลดล้มเหลว และการเปลี่ยนเดือนจากตัวเลือกงบ
- บัญชีอื่น เดือน/query ที่ปลอม และ URL เดิมหลังเปลี่ยนบัญชีไม่เปิดเผยข้อมูลหรือใช้ shared cache

การตรวจ Google OAuth และระบบบน Neon/Vercel จริงยังต้องตั้งค่าตาม [auth-setup.md](auth-setup.md)
