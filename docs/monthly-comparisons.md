# เปรียบเทียบเดือน — issue #11

ใน `/dashboard` ส่วน **เปรียบเทียบกับเดือนก่อน** แสดงรายรับ รายจ่ายสุทธิ และเงินเหลือ พร้อมวันที่เริ่มต้น/สิ้นสุดของทั้งสองช่วง และวันที่อ้างอิงตามเวลาไทย

## กติกาช่วงเวลา

- เดือนปัจจุบัน: วันที่ 1 ถึงวันนี้ตาม `Asia/Bangkok` เทียบวันที่ 1 ถึงเลขวันที่เดียวกันของเดือนก่อน หากเดือนก่อนสั้นกว่าให้จบที่วันสุดท้ายของเดือนก่อน เช่น 1–31 มีนาคม 2024 เทียบ 1–29 กุมภาพันธ์ 2024
- เดือนที่จบแล้ว: เทียบเต็มเดือนที่เลือกกับเต็มเดือนก่อนหน้า แม้จำนวนวันต่างกัน เช่น กุมภาพันธ์ 2024 ทั้ง 29 วัน เทียบมกราคมทั้ง 31 วัน
- เดือนในอนาคตยังไม่มีช่วงเปรียบเทียบ ข้อมูลภาพรวม/งบยังเปิดได้ตามเดิม
- มกราคมปี 0001 ไม่มีเดือนก่อนหน้าภายในช่วงวันที่ที่แอปรองรับ จึงไม่มีช่วงเปรียบเทียบเช่นกัน

แต่ละช่วงรวมวันเริ่มต้นและสิ้นสุด โดย query ใช้ตั้งแต่วันเริ่มต้นถึงก่อนวันถัดจากวันสิ้นสุด ไม่รวมรายการหรือเงินคืนที่อยู่นอกช่วง ระบบใช้ server เป็นแหล่งวันอ้างอิง API ไม่รับ today หรือเวลาจาก client

## ยอดและส่วนต่าง

รายจ่ายสุทธิ = รายจ่ายในช่วง − เงินคืนที่ได้รับในช่วง เงินคืนไม่เพิ่มรายรับและไม่ย้อนลดเดือนของรายจ่ายต้นทาง เงินเหลือ = รายรับ − รายจ่ายสุทธิ

ส่วนต่าง = ยอดช่วงเดือนที่เลือก − ยอดช่วงเดือนก่อน คำนวณด้วยจำนวนเต็มสตางค์/BigInt และแสดงเพิ่มขึ้น ลดลง หรือไม่เปลี่ยนแปลงเป็นจำนวนเงินบาทสองตำแหน่ง

ใช้ส่วนต่างเป็นจำนวนเงินสำหรับทุกฐาน ไม่มีการหารเพื่อแสดงเปอร์เซ็นต์ ฐานศูนย์มีข้อความอธิบายว่าฐานเดือนก่อนเป็นศูนย์ ฐานติดลบแสดงยอดติดลบทั้งช่วงและข้อความอธิบายส่วนต่าง จึงไม่แสดง NaN/Infinity หรือเปอร์เซ็นต์ที่ทำให้ตีความคลาดเคลื่อน สี/ข้อความไม่ได้ตัดสินว่ายอดเพิ่มขึ้นหรือลดลงเป็นผลดีหรือผลเสีย

ตัวอย่าง: รายจ่ายสุทธิเดือนก่อน −10.01 บาท เดือนที่เลือก −17.00 บาท แสดง **ลดลง 6.99 บาท** เงินเหลือยังเป็นกระแสเงินที่บันทึก ไม่ใช่ยอดธนาคารทั้งหมด

## HTTP และการเก็บข้อมูล

`GET /api/dashboard?month=YYYY-MM` เพิ่ม field `comparison` ในรายงานเดิม:

- `mode`: `elapsed` (ช่วงวันที่ผ่านไป) หรือ `full` (เต็มเดือน)
- `asOfDate`: วันที่อ้างอิงไทยของ server
- `current`, `previous`: `startDate`, `endDate`, `income`, `expense`, `refunded`, `netExpense`, `monthlyNet`
- `change`: ส่วนต่าง `income`, `netExpense`, `monthlyNet`

ยอดทั้งหมดเป็นข้อความบาทสองตำแหน่ง กรณีไม่มีช่วงที่เปรียบเทียบได้ `comparison` เป็น `null` การอ่านทั้งภาพรวมและเปรียบเทียบอยู่ใน Repeatable Read transaction เดียวกัน ใช้ User จาก session เท่านั้น และตอบ `Cache-Control: private, no-store` ไม่มี migration เพิ่ม

## การทดสอบวันที่จริงผ่านแอป

`pnpm test:e2e monthly-comparison.spec.ts` สร้าง PostgreSQL แยกและ production server ตามปกติ ชุดทดสอบมี server-clock preloader ที่โหลดเฉพาะคำสั่งเริ่ม server ของ Playwright ไม่ได้ import หรือ compile เข้าแอป และไม่มี endpoint/production switch เปลี่ยนเวลา ตัว preloader ต้องมีฐานทดสอบ local และ clock file ที่ runner สร้างในโฟลเดอร์ชั่วคราวเท่านั้น แต่ละ test เปลี่ยนไฟล์แบบ atomic แล้วคืนเวลาจริงหลังทดสอบ runner ลบโฟลเดอร์เมื่อจบ

HTTP tests กำหนดวัน server จริงของ process ทดสอบ และตรวจช่วง/ยอดผ่าน `/api/dashboard` กับรายการที่กรองผ่าน `/api/transactions` ครอบคลุมกุมภาพันธ์ปีอธิกสุรทินและปีปกติ เดือน 30/31 วัน การเปลี่ยนปี ช่วงเต็มเดือน เทียบถึงวันนี้ รายการหลังวันตัดยอด เงินคืน ฐานศูนย์ ฐานติดลบ และบัญชีอื่น

Browser tests ตรึงเวลา browser ให้ตรง server แต่ใช้ timezone `America/Los_Angeles` ตรวจวันที่อ้างอิงไทยแม้อุปกรณ์ยังอยู่วัน/ปีเก่า รวมการเปลี่ยนเดือนใน Dashboard ช่วงวันที่ที่แสดงจริง ยอด/ส่วนต่าง สถานะไม่มีช่วงเปรียบเทียบ และการแสดงผล desktop/mobile

การตรวจ Google OAuth และ Neon/Vercel จริงยังใช้ขั้นตอนใน [auth-setup.md](auth-setup.md)
