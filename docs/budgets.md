# งบรายเดือน

Issue [#9](https://github.com/tanakron1748q/pocketapp/issues/9)

ใน `/dashboard` ส่วน **งบรายเดือน** เปิดเดือนปัจจุบันตามเวลาไทย เลือกเดือนแล้วกด **ตั้งงบ** ในหมวดรายจ่ายของตัวเอง:

- **เฉพาะเดือนที่เลือก**: มีผลเฉพาะเดือนนั้น และมีลำดับเหนือค่าตั้งต้น
- **ค่าตั้งต้นตั้งแต่เดือนนี้เป็นต้นไป**: ใช้ตั้งแต่เดือนที่เลือกถึงก่อนเดือนที่มีค่าตั้งต้นใหม่ ไม่แก้เดือนก่อนหน้า และไม่ทับเดือนที่มีการปรับเฉพาะไว้

ตัวอย่าง: ตั้งงบมกราคม 1,000 บาทเป็นค่าตั้งต้น ปรับกุมภาพันธ์เป็น 800 บาทเฉพาะเดือน มีนาคมยังใช้ 1,000 บาท หากเปลี่ยนค่าตั้งต้นตั้งแต่มีนาคมเป็น 1,200 บาท มกราคม/กุมภาพันธ์ยังคงเดิม การกลับไปแก้ค่าตั้งต้นเก่ามีผลต่อเดือนถัดจากค่านั้นจนถึงค่าตั้งต้นใหม่ เดือนที่ override ไว้ยังคงใช้ override

งบรับทศนิยมไม่เกินสองตำแหน่ง ตั้งแต่ 0 ถึง 21,474,836.47 บาท เก็บเป็นจำนวนเต็มสตางค์ 0 เป็นงบที่ระบุชัดเจน แยกจากหมวดที่ยังไม่ตั้งงบ ตั้ง 0 เฉพาะเดือนเพื่อหยุดใช้งบเดือนนั้น หรือตั้ง 0 เป็นค่าตั้งต้นเพื่อหยุดตั้งแต่เดือนนั้นเป็นต้นไป

ใช้ไป = รายจ่ายในหมวดและเดือนนั้น − เงินคืนของหมวดในเดือนที่ได้รับจริง

คงเหลือ = งบเดือนนั้น − ใช้ไป

ไม่มีการทบงบเหลือข้ามเดือน หากเงินคืนมากกว่ารายจ่ายในเดือนนั้น ใช้ไปอาจติดลบและงบคงเหลือมากกว่างบตั้งต้นได้ ใช้เกินงบจะแสดงจำนวนเกิน พร้อมให้บันทึกรายจ่ายต่อได้ การแก้รายจ่าย/เงินคืนหรือย้ายหมวดต้นทางสะท้อนในงบเมื่อโหลดใหม่ การบันทึกผ่านหน้าจอเดียวกันจะโหลดงบใหม่อัตโนมัติ

หมวดที่เก็บแล้วแสดงในประวัติเมื่อมีงบหรือรายการในเดือนนั้น แต่ตั้งงบใหม่ไม่ได้ เปลี่ยนชื่อหมวดแล้วงบแสดงชื่อใหม่

## HTTP

ทุกคำขอตรวจ session ใช้ User จาก session เท่านั้น และตอบ `Cache-Control: private, no-store`

- `GET /api/budgets?month=YYYY-MM`: งบ/ค่าตั้งต้น/override/ใช้ไปสุทธิ/คงเหลือของหมวดรายจ่ายส่วนตัว หากไม่ระบุเดือนใช้เดือนปัจจุบันเวลาไทย `amount: null` หมายถึงยังไม่ตั้งงบ
- `PUT /api/budgets`: JSON `{ "categoryId": "…", "month": "2026-10", "scope": "DEFAULT", "amount": "1000.00" }` หรือ scope `MONTH` บันทึกซ้ำด้วย key เดิมแทนค่าเดิม ตอบ `{ "saved": true }` แล้วโหลดรายงานใหม่

PUT ต้องมี Origin ตรงกับ `BETTER_AUTH_URL` ไม่รับ userId หรือ field เกิน schema ข้อมูลผิดตอบ 422 เดือนใน query ผิดตอบ 400 ไม่มี session ตอบ 401 หมวดของบัญชีอื่น/หมวดรายรับ/หมวดที่เก็บแล้ว/หมวดที่ไม่มีอยู่ตอบ 404 โดยไม่เปลี่ยนข้อมูล

Migration `20261029010000_monthly_budgets` เพิ่มตาราง `budget_settings` และ constraints สำหรับงบไม่ติดลบ วันแรกของเดือน และ FK ผูกเจ้าของกับหมวดรายจ่าย พร้อม unique key ป้องกันแถวซ้ำ หมวดถูกล็อกระหว่างบันทึกเพื่อไม่แข่งกับการเก็บหมวด

## การตรวจรับ

`pnpm test:e2e budgets.spec.ts` ทดสอบ browser/HTTP บน desktop และ mobile ด้วย PostgreSQL แยก: ค่าตั้งต้นข้ามปี override งบศูนย์ ไม่ทบยอด เงินคืนข้ามเดือน หมวดแก้ไข/เก็บแล้ว งบติดลบและการบันทึกต่อ persistence ข้ามอุปกรณ์ validation สิทธิ์สองบัญชี retry และร่างที่คงอยู่เมื่อบันทึกล้มเหลว

การทดสอบอัตโนมัติใช้ session fixtures เดิมของโปรเจกต์ การตรวจจริงกับ Google/Neon/Vercel ยังต้องตั้งค่า credentials ตาม [auth-setup.md](auth-setup.md)
